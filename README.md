# 冷静一下 · 小程序 MVP

消费决策 + 冷静期 + 陌生人审批。用户提交想买的商品和理由，冷静期内由他人投票给建议，到期后由本人最终决定"买"或"放弃"，放弃金额累计为"省下了"。

本目录是**可导入微信开发者工具的完整 MVP 代码**，不是概念方案。

**直接打开就能用**：项目默认是「演示模式」——不用 AppID、不用云环境、不用上传云函数，数据存在本机，导入即可点通完整闭环。想上真机/上线时，只需改 `utils/config.js` 一处（见第二节）。

**定稿边界（2026-11-17 确认）**：不接微信支付、不做会员/打赏、不复用「睡一觉再买」。产品是纯工具，目标只有留存与冷静期有效性。

## 二、打开方式

### A. 演示模式（默认，零配置，推荐先看这个）

1. 打开微信开发者工具 → 「导入项目」→「目录」选**仓库根目录**（就是有 `project.config.json` 的那一层）：

   ```
   <你 clone 或解压出来的路径>/miniapp-cooldown
   ```

   > 注意是 `miniapp-cooldown` 这一层，**不要**再往里选到 `miniprogram`（那里没有 `project.config.json`，导入会失败）。

2. AppID 选「测试号」或直接留游客 AppID（无需你自己的账号），点确定。仓库里的 `project.config.json` 已写成 `touristappid`，任何人都能直接跑；换成你自己的 AppID 见 B 节第 1 步。
3. 编译即可用。数据存在本机，`utils/config.js` 里 `CLOUD_ENV` 还是占位符时自动走演示模式。

演示模式默认是**空库**（存储 key `demo_cooldown_db_v2`）：广场和"我的"都没有数据，省钱账本 ¥0——所有决策单由你自己发起，从零开始。旧版预置数据会在重新编译时自动清理，无需手动操作。发起后完整闭环都能点：

- 发起审批 → 广场出现新单 → 详情投票（不填理由会拦、投过一次会拦）→ 举报
- 「我的」页底部有 **「让所有冷静期立即到期」** 按钮，点完回详情即可测结算；选"放弃"后省钱金额立刻累加
- 结算前的冷静期锁定、重复投票拦截、省钱累加逻辑都与云端一致（同一套返回结构和错误码）

> 演示模式的数据只在本机，清缓存/换设备会重置。订阅消息在演示模式下会提示"需云端配置"（属正常，它依赖真实模板 ID）。

### B. 切换真实云端（要真机/上线时再做）

只需改 **`miniprogram/utils/config.js` 一个文件**：把 `CLOUD_ENV` 从占位符换成你的云环境 ID（形如 `xxx-1gxxxxxx`）。保存后 `DEMO_MODE` 自动变 `false`，`api.js` 会自动改走云端，其余代码不用动。然后：

1. `project.config.json` 的 `appid` 换成你的小程序 AppID。
2. 开发者工具 → 云开发 → 开通（按官方最新流程；基础库版本以官方文档为准）。
3. 建数据库集合和索引，严格按 [`database/README.md`](./database/README.md)。**`votes` 的唯一索引不建，一人一票会被并发绕过。**
4. 上传云函数：`cloudfunctions/` 下**每个**子目录右键 →「上传并部署：云端安装依赖」，共 **11 个**，一个都不能漏（`login` 漏了开不了页面）。`dailyAggregate` 要连同 `config.json` 一起上传，否则定时触发器不注册。
5. 替换两处订阅消息模板 ID（保持一致）：

| 文件 | 占位符 | 换成 |
|---|---|---|
| `miniprogram/pages/detail/detail.js` | `SUBSCRIBE_TEMPLATE_ID` | 你的订阅消息模板 ID |
| `cloudfunctions/subscribePush/index.js` | `TEMPLATE_ID` | 同上 |

> 模板 ID 还没申请时，detail.js 会拦截点击并提示"请先在公众平台配置模板 ID"，不影响其他功能。

### C. 云端双账号验收

切换云端后，用**两个微信号**（或开发者工具多账号模拟）跑这条链：

用**两个微信号**（或开发者工具多账号模拟）跑这条链：

1. A 打开小程序 → 自动静默登录 → 「发起审批」填商品/金额/理由 → 选 1 小时冷静期 → 提交。
2. B 进入审批广场 → 看到 A 的单 → 进详情 → 不填理由点投票 → 应提示"请写下至少 2 个字"。
3. B 填理由投「建议别买」→ 再投一次 → 云函数应返回"你已经投过票了"（唯一索引生效）。
4. A 进详情 → 冷静期内点「还是买了」→ 应提示"冷静期还没结束"（服务端校验生效）。
5. 1 小时后（或调试时把 `expireAt` 改到过去）→ A 点「我放弃了」→ 「我的」页省钱金额 = 该商品价格。
6. B 在详情页点举报 → 不选原因提示必填 → 填原因提交 → 云函数写入 reports。
7. 首次启动：隐私弹窗必须先同意才可使用；同意状态本地持久化，二次进入不再弹。
8. 下拉刷新、分页加载、分享卡片各点一遍。

## 三、技术约定（改代码前先看）

- **金额一律用「分」**，前端只在展示层 `yuan()` 转元；`toFen()` 只做两位小数转换。
- **所有云函数返回 `{ code: 0, data, msg? }`**，非 0 由 `utils/api.js` 统一 toast。
- **时间判定全在服务端**：`expireAt` 由 `decisionPublish` 用服务端时间算，`settle` / `vote` 用 `Date.now()` 比较，前端倒计时只做展示。
- **openid 不下发**：列表和详情都做了脱敏，只有 `isMine` 布尔值。
- **内容安全内联**：每个需要审核的云函数各自内联 `msgSecCheck`，不跨云函数 `require`（独立部署目录运行时不存在）。
- **定时器必须清理**：`countdown` 组件在 `detached` 里 `clearInterval`，否则切页后内存泄漏。

## 四、明确不做的事（定稿边界）

| 项 | 状态 | 说明 |
|---|---|---|
| 微信支付 / 商户号 | ❌ 永久不做 | 无 `payCreateOrder` / `payCallback`，无 `orders` 集合，前端无 `wx.requestPayment` |
| 会员 / 打赏 / 商品代购 | ❌ 永久不做 | 无 `pages/member`；`users.memberLevel` 恒为 `free`，不参与任何逻辑 |
| 「睡一觉再买」三理论引擎 | ❌ 不复用 | 本产品独立成立，无代码/数据/文档耦合 |

代价说清楚：**放弃打赏这条唯一被验证过的收入路径**（同类百万用户产品只赚到 28 元）。换来的是零支付资质门槛、零回调可靠性问题、零 iOS IAP 冲突。**本产品短期没有商业模式，不要按变现项目排期。**

## 五、已知限制

- **无收入**：纯工具，长期运营成本（云开发资源）需要另行考虑。
- **UGC 内容安全是上线命门**：`msgSecCheck` 接口版本/参数以官方文档核实；未开通会直接导致提审被拒。
- **生命周期风险**：工具型热点衰减快，代码按模块拆分，方便快速转向。
- **举报无人工后台**：`reports` 集合只做留痕，处理端需另行开发（V2）；当前依赖内容安全前置拦截。
- **订阅消息需用户逐次授权**：不是无限推送，模板字段要按实际申请的模板调整。
- **隐私保护指引需后台配置**：代码层已做首次启动说明弹窗，公众平台的《用户隐私保护指引》仍需自行填写。
